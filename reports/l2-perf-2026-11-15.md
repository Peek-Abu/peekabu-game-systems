# l2-perf: freezes and hitches before launch (2026-11-15)

Session: launch perf push. Branch: `game/cleanup-crew`. Launch List row `l2-perf`.

## How it was measured

- Studio Play on this machine, with two Studios open and other sessions working, so the absolute numbers are high.
  Compare before and after; don't read them as a phone's numbers.
- Studio slows an unfocused window to 15 fps. Frame times of 66 ms are that throttle, not the game. Hitches are the
  frames well above it. The engine's own `Stats.RenderCPUFrameTime` is not throttled and is listed beside them.
- The script profiler can't be started from a game script ("lacking capability Plugin"), so work was timed with
  timestamps: frame phases (RenderStepped, PreAnimation, PreSimulation, PostSimulation), wrapped module functions,
  and instance counts.

## Lobby: what costs what (before)

| Moment | Worst frame | What it is |
|---|---|---|
| Open the Shop | 121-187 ms | 100-150 ms of main-thread work in one frame; the Shop adds 3,138 instances |
| Close the Shop | 100-185 ms | the same instances destroyed in one frame |
| Open the Inventory | 95-123 ms | adds 1,036 instances |
| Open a skin page (live hero) | 91-157 ms | |

What the 3,138 Shop instances are: 686 Parts, 635 WeldConstraints, 206 MeshParts, then UI (417 Frames, 218 UIStrokes,
186 UICorners, 131 UIGradients...). The preview builds themselves (`EmployeePreviewSystem.static`, cached and cloned)
are only 39 ms of Lua across 8 calls.

**Root cause: the lanyard strap.** Every strap is built from 96 separate Parts:
- Previews (`attachPreview`) always use the Part fallback.
- Real characters do too, because the EditableMesh API is refused ("EditableMesh is not accessible. Go to the Security
  Tab in Experience Settings"). Pippa: 96 of her 140 parts are strap.
- So each Shop card was ~140-170 instances, two-thirds of them strap. Cloning 12 cards into ViewportFrames took
  43-63 ms with straps and 14-32 ms without; destroying them 18-22 ms vs 5-14 ms.

Does the published game get the 96-Part strap too? Yes, as things stand. The EditableMesh API is gated by the one
Game Settings > Security toggle "Allow Mesh & Image APIs", which applies to Studio Play and to the published game
alike, and Studio Play refuses it. Turning it on needs the experience owner (for a group game, the group owner) to be
13+ and ID-verified ([EditableMesh docs](https://create.roblox.com/docs/reference/engine/classes/EditableMesh),
[announcement](https://devforum.roblox.com/t/client-beta-in-experience-mesh-image-apis-now-available-in-published-experiences/3267293)).
Previews use the Part strap either way (`attachPreview` builds synchronously). So the fix below matters live, and it
matters in Studio, where the owner tests.

live server the client only pays its own part (the map arriving).

## Fixes

1. `ba28857b` lanyard: the Part strap is built from the fewest straight runs that stay within a tolerance of the
   fitted strap (`EmployeeLanyardFormulas.ribbonRuns`), instead of one Part per station. Characters 0.01 studs
   (14-67 Parts by employee and rank), previews 0.02 (8-39).

### After (Lobby, Studio Play, the fix synced)

"Longest work" is the longest stretch between two frame-phase markers in one frame (the 15 fps throttle can't inflate
it); before numbers are from the same probe.

| Moment | Before | After |
|---|---|---|
| Shop open, longest work | 101-150 ms | 58-99 ms (3 opens) |
| Shop close | 126 ms | 59-83 ms |
| Inventory open | 62 ms | 27-47 ms |
| Instances the Shop adds | 3,138 (686 Parts, 635 welds) | 2,396 (175 Parts, 252 welds) |
| Pippa as a player | 140 parts, 96 of them strap | 69 parts, 25 strap |
| Static card, instances | Pippa 139, Cappy 169, Prickles 142 | 57, 100, 67 |

- Full TestEZ (Lobby): 6948 passed, 0 failed.
- Close-ups (`l2-perf/strap-*.jpg` in the notes folder, and the owner page
  https://claude.ai/artifact/91AkucwGQ9n4KYZpA51ffW): at an extreme close-up the 25-part player strap shows tiny steps
  near the shoulder; the 14-part card strap is angular that close. If the owner wants the player strap smoother,
  `PART_RIBBON_TOLERANCE` 0.005 gives ~47 parts.
2. `0a40d407` Shop card staggering: a still preview card mounts its model from `UIBuildQueueSystem` (about 4 ms of
   clones a frame, at least one) instead of in the frame its screen opens; live heroes, emotes and reveals mount at
   once. Measured A/B in one Lobby Play by swapping the queue for an immediate run, alternating Shop opens:
   - queue on: 86, 83, 99, 75, 100, 80, 74 ms longest work (median 83);
   - queue off: 110, 149, 96, 99, 116, 129, 110 ms (median 110);
   - the Shop's 14 viewports fill within ~0.5 s at Studio's throttled 15 fps (~7 frames, about 0.1 s at 60 fps); the
     Inventory's 9 within ~0.3 s.
   - Full TestEZ (Lobby): 6957 passed, 0 failed.
- Left: the Shop open is still one ~80 ms frame in Studio. That is the UI itself (~1,400 UI instances built by React
  in one commit). Cutting it means building the Shop's tabs lazily or keeping the screen mounted between opens; both
  are UI-structure changes, not done before launch.

3. Owner picks 11-15 "go with b and c! (settings changed!)":
   - b, `e3121fcb`: Shop and Inventory item previews leave the rank lanyard off (`EmployeePreviewSystem.static/live`
     `lanyard = false`, `ToonViewport` `lanyard` prop, the preload warms bare looks). Kept on your own look: try-on
     outfits, the Inventory employee page's hero and title art, the real character, portraits. Still on (owner to
     decide): the pick screen, locker/deal/reveal previews, the training coach.
   - c, no code: "Allow Mesh & Image APIs" is on, and the existing path (`buildStrapMesh` first, Part fallback when it
     fails) now builds the strap as one MeshPart on real characters. Checked in a Lobby Play: Pippa's character 1
     mesh strap and 45 parts (140 this morning, 69 with the Part fix); `EmployeeLanyardSystem.attach` on Pippa, Cappy
     and Prickles copies built one mesh each, and they look right (`l2-perf/mesh-strap-*.jpg`).
   - Shop open now adds 2,051 instances (50 Parts, 209 welds) vs 2,396 / 175 / 252. Longest work for Shop open is
     unchanged within noise (85-105 ms over 4 opens, throttled Studio): the cards already load a few per frame.
   - `98d16a39`: the module map lists `UIBuildQueueSystem` again (it had dropped out of an earlier push).
   - Full TestEZ (Lobby): 6959 passed, 0 failed.
