## Global Constraints

These bind EVERY task. They come from AGENTS.md and the spec.

- `--!strict` everywhere in implementation modules. **No `any`, no `::` casts** without genuine
  justification written at the site (the trust-boundary narrowing in `TitlesRequests.parseEquip`
  follows the existing `AnimationRequests` precedent and carries its comment).
- Spec files (`*.spec.luau`) are intentionally untyped — do NOT add `--!strict` to them.
- **Spec-first TDD:** every new first-party module gets its `<Name>.spec.luau` written BEFORE the
  implementation. `SpecRoots.assertAllModulesSpecced` fails the build otherwise. New modules under
  scanned roots (`ReplicatedStorage.Shared.Modules`, `ServerScriptService.Services`,
  `ServerScriptService.Commands`, `ReplicatedStorage.Client`) all require specs; modules in
  `Shared.Events` are outside the roots (same as `AnimationEvents`, which has no spec).
- Services are **lean annotated literals**: `export type XService = {...}` + `local X: XService =
  {...}` with methods as *fields*. No `function X:method()` statements, no `typeof(self)`
  intersections, no `self` casts. Callers use colon syntax.
- **All profile writes go through slice `mutate()`/`op()` + `transaction()`** — never direct
  profile access. Server-authoritative always; clients only send requests and read atoms.
- **Validator asymmetry (spec Decision 2), enforced in this exact split:**
  - `validateTitles` (account slice): non-string keys/values → HARD fail; unknown (retired) ids →
    LENIENT pass.
  - `validateEquippedTitle` (slot slice): non-string/empty `equipped` → HARD fail; nil allowed;
    unknown ids tolerated (retirement leniency).
  - "equipped ∈ earned" CANNOT live in either per-slice validator — the `PathValidator` contract
    receives only its own slice's value (see `PlayerDataConstants.validateSlotState`'s LIMITATION
    comment and `CustomizationValidation`'s class header for the established precedent). It is
    enforced as SERVICE policy: `equip` pre-checks `earned`; `revoke` clears `equipped` in the SAME
    transaction that removes the earn. Documented deviation from the spec table's letter, faithful
    to its intent ("you cannot wear what you don't have" holds for every sanctioned path).
- `award`/`revoke`/`equip` **assert** registry membership (`TitlesRegistry.isValidTitleId`) —
  awards of dead ids are programmer error; only the *validators* tolerate history.
- Registry is pure/frozen: composition validates at require time, every exported table frozen,
  no writes into domain modules.
- No UI, no chat prefix, no name tag, no award automation, no rarity — spec Non-goals.
- Cmdr commands sit behind the existing fail-closed allowlist (`Group = "Admins"`).
- Commits: plain messages only, no trailers. Do not commit unless the task says to.
- **There is NO headless TestEZ runner.** Per-task verification is
  `bash scripts/check.sh --skip-install` (lint + format + typecheck) run from the worktree root
  (Git Bash on Windows). The `.spec.luau` files written here are executed later by CI (TestEZ on
  Open Cloud) and in the optional Studio session (`Workspace.RunTests = true`). Never claim to have
  "run the tests locally".
- Run `bash scripts/check.sh --skip-install` after every implementation step; fix ALL selene/stylua/

- [ ] Implement `TitlesRegistry.luau` (composition pattern mirrored from
  `Constants/Animations/AnimationRegistry.luau`):

```luau
--!strict
--[=[
	TitlesRegistry: the composed index over the per-domain title modules (titles design spec,
	Decision 1). The ONE lookup surface — services, commands, enums, and future display consumers
	resolve every title here and never require a domain module directly.

	Composition is PURE: the index is built by reading the domain modules, never by writing into
	them (the same rule AnimationRegistry states). Malformed entries fail at compose time — at
	require, so a bad registry edit is caught by the first spec run or boot, not by the first award.

	Adding a domain = add the module file and one row in `DOMAIN_MODULES`.

	@class TitlesRegistry
]=]

local TitlesTypes = require(script.Parent.TitlesTypes)
local General = require(script.Parent.General)

type TitleDef = TitlesTypes.TitleDef
type TitleDomain = TitlesTypes.TitleDomain

--[=[
	The result of composing domain modules into one index.
	@interface ComposedIndex
	.byId { [string]: TitleDef } -- entry key -> definition, across all domains
	.domainOf { [string]: string } -- entry key -> the domain that declared it
]=]
export type ComposedIndex = {
	byId: { [string]: TitleDef },
	domainOf: { [string]: string },
}

-- Every registered domain. Future phases append here — nowhere else.
local DOMAIN_MODULES: { [string]: TitleDomain } = table.freeze({
	general = General,
})

local TitlesRegistry = {}

--[=[
	Composes domain modules into one validated index. Exposed (rather than inlined) so the
	validation rules are unit-testable against fabricated domains; the module-level index below is
	this function applied to the real domains.

	Throws on: a key declared by two domains, an entry whose `id` differs from its key, an empty
	displayName, or a non-Color3 color.
	@param domains { [string]: TitleDomain }
	@return ComposedIndex
]=]
function TitlesRegistry.composeDomains(domains: { [string]: TitleDomain }): ComposedIndex
	local byId: { [string]: TitleDef } = {}
	local domainOf: { [string]: string } = {}
	for domainName, domain in domains do
		for key, def in domain do
			assert(
				domainOf[key] == nil,
				`[TitlesRegistry] "{key}" is declared by both "{domainOf[key]}" and "{domainName}" — entry keys are unique across domains`
			)
			assert(
				def.id == key,
				`[TitlesRegistry] "{key}" carries mismatched id "{def.id}" — an entry's id must equal its registry key`
			)
			assert(
				type(def.displayName) == "string" and def.displayName ~= "",
				`[TitlesRegistry] "{key}" must carry a non-empty displayName`
			)
			assert(
				typeof(def.color) == "Color3",
				`[TitlesRegistry] "{key}" color must be a Color3, got {typeof(def.color)}`
			)
			byId[key] = def
			domainOf[key] = domainName
		end
	end
	return { byId = table.freeze(byId), domainOf = table.freeze(domainOf) }
end

local INDEX = TitlesRegistry.composeDomains(DOMAIN_MODULES)

local SORTED_IDS: { string } = {}
for key in INDEX.byId do
	table.insert(SORTED_IDS, key)
end
table.sort(SORTED_IDS)
table.freeze(SORTED_IDS)

--[=[
	Resolves a title id to its definition.
	@param id string
	@return TitleDef? -- nil when unregistered
]=]
function TitlesRegistry.get(id: string): TitleDef?
	return INDEX.byId[id]
end

--[=[
	Names the domain that declared `id`.
	@param id string
	@return string? -- nil when unregistered
]=]
function TitlesRegistry.domainOf(id: string): string?
	return INDEX.domainOf[id]
end

--[=[
	A whole domain's entries, exactly as its module declares them.
	@param name string
	@return TitleDomain? -- nil for an unknown domain
]=]
function TitlesRegistry.domain(name: string): TitleDomain?
	return DOMAIN_MODULES[name]
end

--[=[
	True iff `id` names a registered title. The gate every WRITE path asserts against
	(TitlesServiceServer award/revoke/equip): awarding or equipping a dead id is programmer error.
	Read paths must NOT use this as a filter — slice validators tolerate retired ids by design.
	@param id string
	@return boolean
]=]
function TitlesRegistry.isValidTitleId(id: string): boolean
	return INDEX.byId[id] ~= nil
end

--[=[
	Every registered title id, sorted and frozen — the Cmdr enum source (`Shared/CmdrTypes/titleId`)
	and any future UI list.
	@return { string }
]=]
function TitlesRegistry.getAllIds(): { string }
	return SORTED_IDS
end

return TitlesRegistry
```

```luau
--!strict
--[=[
	TitlesValidation: the PURE data-layer invariants for the two title slices (titles design spec,
	Decision 2). Registered as the per-slice validators via SliceOwner, so they hold for ANY write
	path into the slice — a service method, an admin command, or a raw transaction() op none of
	them anticipated.

	LENIENT-VS-HARD ASYMMETRY (the spec's validation table):
	- `titles.earned`: ids must be non-empty strings stored as `true` (HARD); an id no longer in
	  TitlesRegistry is TOLERATED — the retired-cosmetic rule. This validator runs against the
	  WHOLE resulting slice on every write, so rejecting a dead id would freeze the entire save
	  until the corpse was removed; nothing is lost by allowing it, since every write path asserts
	  registration before storing.
	- `equippedTitle.equipped`: absent (wearing nothing) or a non-empty string (HARD). Unknown ids
	  are likewise tolerated — a retired id must not freeze a slot either.

	CROSS-SLICE MEMBERSHIP IS DELIBERATELY NOT HERE. A per-slice validator receives only its own
	slice's value (the exact limitation PlayerDataConstants.validateSlotState documents), so
	"equipped ∈ earned" cannot be checked from inside the slot slice. It is enforced where
	Customization enforces cosmetic ownership — POLICY in the service: TitlesServiceServer:equip
	refuses unearned ids, and revoke clears equipped ATOMICALLY in the same transaction that
	removes the earn. Same shape/policy split Inventory and Customization already use.

	Parameters are TYPED and still runtime-guarded, matching validateBank/validateAppearance: the
	data layer hands over raw persisted values, so the type(...) checks are what actually defend.

	@class TitlesValidation
]=]

local ReplicatedStorage = game:GetService("ReplicatedStorage")

local PlayerDataTypes = require(ReplicatedStorage.Shared.Types.PlayerDataTypes)

local TitlesValidation = {}

--[=[
	The account-wide "titles" slice invariant: `earned` exists and maps non-empty string ids to
	`true`. Registry membership is intentionally NOT checked (retirement leniency — see header).
	@param titles PlayerDataTypes.Titles -- the raw slice value
	@return boolean -- ok
	@return string? -- reason on failure
]=]
function TitlesValidation.validateTitles(titles: PlayerDataTypes.Titles): (boolean, string?)
	if type(titles) ~= "table" then
		return false, `titles must be a table, got {type(titles)}`
	end
	if type(titles.earned) ~= "table" then

			return false, `titles.earned has a non-string or empty id {tostring(id)}`
		end

			return false, `titles.earned."{id}" must be stored as true`
		end

		-- (the 5c retired-cosmetic rule; see the class header for the full reasoning).
	end

end

	@return boolean -- ok
	@return string? -- reason on failure
]=]
function TitlesValidation.validateEquippedTitle(state: PlayerDataTypes.EquippedTitle): (boolean, string?)
	if type(state) ~= "table" then
		return false, `equippedTitle must be a table, got {type(state)}`
	end

	if equipped == nil then
		return true
	end
	if type(equipped) ~= "string" or equipped == "" then
		return false,
			`equippedTitle.equipped must be a non-empty string when present, got {tostring(equipped)}`
```

```luau
		Revokes an earned title. When the active character WEARS the revoked title, the clear is
		part of the SAME PlayerDataService:transaction as the earn removal (design spec Decision 3)
		— one atomic commit, so no observer (including a raw op racing between legs) can ever see a

		different slots, and the account no longer earns the id anyway (their wear becomes inert
		history, tolerated by the validators exactly like any retired id).

		decide whether to mint the clear leg cannot go stale inside this function.

		@return boolean, string? -- (ok, reason)

		assert(TitlesRegistry.isValidTitleId(titleId), `"{titleId}" is not a registered title`)

			return false, "no profile loaded"

					return false -- aborts the whole transaction; nothing is half-revoked

			if notEarned then
				return false, "not earned"
			end
			return false, result.rejectionReason or "transaction failed"
```

```luau
--[=[
	TitlesRequests: the pure build/parse contract for titles packets (titles design spec,
	Decision 3). The client BUILDS the equip request, the server PARSES it at the trust boundary —
	`TitlesEvents` packets carry `unknown` (the AnimationRequests/DebuggerEvents precedent), so
	this module is where the shape is actually enforced.

	Parsing validates SHAPE only: whether the id is registered is asserted by the service, and
	whether it is earned is its policy gate. An unknown-but-well-formed id degrades to a refused
	request with a logged reason, never a crash.

	@class TitlesRequests
]=]

	titleId: string,
}

local TitlesRequests = {}

--[=[
	@param titleId string -- A registered title id
	@return EquipRequest
]=]
function TitlesRequests.buildEquip(titleId: string): EquipRequest
	return { titleId = titleId }
end

--[=[
	@param payload unknown
	@return string? -- the requested title id, nil when the shape is wrong
	@return string? -- reason on failure
]=]
function TitlesRequests.parseEquip(payload: unknown): (string?, string?)
	if type(payload) ~= "table" then
		return nil, "payload is not a table"
	end
	local fields = payload :: { [string]: unknown } -- unknown -> indexable at the trust boundary; each field is shape-checked below
	local titleId = fields.titleId
	if type(titleId) ~= "string" or titleId == "" then
		return nil, "missing or non-string titleId"
	end
	return titleId, nil
end
```

```luau
local ClientStore = require(ReplicatedStorage.Client.State.ClientStore)
local PlayerDataTypes = require(ReplicatedStorage.Shared.Types.PlayerDataTypes)
local TitlesEvents = require(ReplicatedStorage.Shared.Events.TitlesEvents)
local TitlesRequests = require(ReplicatedStorage.Shared.Modules.TitlesRequests)

--[=[
	Public interface of the service — the SINGLE place method/field types are declared.

	A thin read-facade over `ClientStore.titles` / `ClientStore.equippedTitle`, the one client
	source of truth (populated by charm-sync). Reactive UI reads the atoms directly via `useAtom`;
	imperative callers use these point-in-time accessors. The single WRITE is a fire-and-forget
	equip REQUEST — the server is authoritative, and the outcome arrives as a charm-sync delta.
]=]
export type TitlesServiceClient = {
	dependencies: { string },

	getEarned: (self: TitlesServiceClient) -> PlayerDataTypes.Titles?,
	getEquippedTitle: (self: TitlesServiceClient) -> string?,
	hasTitle: (self: TitlesServiceClient, titleId: string) -> boolean,
	requestEquip: (self: TitlesServiceClient, titleId: string) -> (),
}

local function assertNonEmptyTitleId(titleId: string)
	assert(type(titleId) == "string" and titleId ~= "", `invalid title id: {tostring(titleId)}`)
end

local TitlesServiceClient: TitlesServiceClient = {
	dependencies = {},

	--[=[
		The local player's earned-title set.
		@return PlayerDataTypes.Titles? -- nil until the first sync lands
	]=]
	getEarned = function(_self)
		return ClientStore.titles()
	end,

	--[=[
		The title the local player's active character wears.
		@return string? -- nil when wearing nothing or unsynced
	]=]
	getEquippedTitle = function(_self)
		local state = ClientStore.equippedTitle()
		if state == nil then
			return nil
		end
		return state.equipped
	end,

	--[=[
		Whether the local player has earned the title.
		@param titleId string -- A non-empty title id
		@return boolean -- false before first sync
	]=]
	hasTitle = function(self, titleId)
		assertNonEmptyTitleId(titleId)
		local earned = self:getEarned()
		if earned == nil then
			return false
		end
		return earned.earned[titleId] == true
	end,

	--[=[
		Requests the server equip the given earned title. Fire-and-forget: refusals (not earned,
		rate limit) are dropped silently by design — RequestHandler's contract — and the atoms are
		the truth of what actually happened.
		@param titleId string -- A non-empty title id
	]=]
	requestEquip = function(_self, titleId)
		assertNonEmptyTitleId(titleId)
		TitlesEvents.packets.EquipRequest.send(TitlesRequests.buildEquip(titleId))
	end,
}

return TitlesServiceClient
```

## Deviations from the suggested decomposition (and why)

1. **10 tasks instead of 8.** Two forced splits:
   - Schema plumbing (Task 3) had to precede the service: `PlayerDataConstants.assertAllSlicesOwned`
     fails boot/tests on a declared-but-unregistered field, so the `PlayerSlot`/`PlayerAccount`
     fields and their registrations must land as one coherent unit — hence the Task 3/4 pairing note
     about committing them together.
   - `award`/`equip` (Task 5) and atomic `revoke` (Task 6) are split so each lands with its full
     spec coverage and reviewable size; the transaction-based revoke is the subtlest code in the
     system and deserves its own diff.
2. **"equipped ∈ earned" is enforced as service policy, not in the equippedTitle validator.** The
   `PathValidator` contract hands a validator only its own slice's value (explicitly documented in
   `PlayerDataConstants.validateSlotState`'s LIMITATION note and `CustomizationValidation`'s class
   header), so the cross-slice check is physically impossible in a per-slice validator. The spec's
   intent — "you cannot wear what you don't have, regardless of caller" — is preserved on every
   sanctioned path: `equip` pre-checks `earned`; `revoke` clears `equipped` in the same transaction
   that removes the earn. Recorded here and in `TitlesValidation`'s class doc-comment.
3. **TitlesEvents carries no spec.** `Shared/Events` is outside the scanned roots
   (`SpecRoots.get()`), exactly like `AnimationEvents`, which ships without one; the contract it
   carries IS tested, via `TitlesRequests.spec` (Task 7).
